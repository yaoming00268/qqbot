## 对话人设与共享代理

重开 `run_gui.bat`，进入 **对话与代理**。选择已知对话，或点“添加对话”，选择账号并填写群号或私聊用户 ID；官方通道填写平台提供的 openid。选择运行方式后点“保存对话设置”，下一条消息生效。

| 运行方式 | 人设、会话与记忆 | 空闲自由活动 |
| --- | --- | --- |
| 独立 | 各自选择人设，各自保留模型会话和历史 | 沿用原有设置 |
| 合并 | 指定一个主对话，成员统一使用其人设、持久模型上下文与共享记忆索引 | 同一共享组只调度一次 |
| 跟随 | 当前对话作为主代理的另一个入口，沿用主对话的人设、上下文与记忆 | 跟随入口不单独触发，使用主对话的空闲上下文 |

例如先为群 A 选好人设，再把群 B 和私聊 C 的运行方式改为“合并”或“跟随”，主对话都选 A，三个入口即可使用一个持久模型上下文。界面显示已知对话数量和使用的上下文数量。共享仅支持同一账号，允许群聊与私聊混合；不会跨 QQ 账号或官方 / OneBot 通道关联，循环关联会被拒绝。

共享后，这些入口的聊天内容与记忆会供同一代理使用。回复仍发往本轮来源，主人、管理员、文件与工作授权按实际来源判断。多个入口的消息按共享会话排队，后台成果按原来源领取。角色绑定使用稳定 ID，重命名后仍有效。

历史文件保留原处，已有摘要与记录通过去重索引按需读取，不自动拼接或删除旧会话。改回“独立”并选回原人设，可继续使用原来的独立会话；共享期间写入主代理的历史保留在主代理中，不自动复制到每个入口。“恢复默认设置”会移除当前入口的专门规则，人设回到全局或原群设置；其他入口指向它的关联仍保留。

这一功能通过复用持久会话、人设预设和已读记忆缓存减少重复输入；新增消息、按需读取的历史及模型自身的上下文仍会消耗 token，实际节省取决于消息量与后端计费方式，不保证固定比例。配置保存在 `bot.conversations`，默认空配置兼容现有独立对话。

## 双语命令与任务队列

主代理启动时读取固定的 [操作规范](G:/qqbot/console_tools/MAIN.md) 和 [CLI 接口表](G:/qqbot/console_tools/API.md)，会话首次接入或协议变化时加载一次。日常输入只送新消息、相关附件和状态变化，无关旧图片、重复识别描述和空协议字段不再随每轮发送。

普通回复用 `qqbot_reply(context_file,text)` 一次提交正文并显式结束；需要继续工具时设置 `continue_work=true`。`reply/commit` 提交后立即发送正文，`finish` 只结束回合。同轮可以先确认准备、安排后台任务、再补发结果；后台执行等待确认消息回执，同会话仍按完整回合排队。

发送 `/help` 或 `/帮助` 查看完整中英文命令和权限。支持空格及中英文冒号，例如 `/code：写一个带测试的计算器`、`/图片 雪中的猫`、`/处理 将附件转成表格`；明确的斜杠命令无需另 @。

主人设置包括 `/botname` `/机器人名称`、`/persona` `/性格`、`/nickname` `/昵称 @成员 新称呼`、`/length` `/字数`、`/files` `/文件`、`/frequency` `/频次`。管理员或主人可用 `/file-size` `/文件大小` 和 `/bug` `/提示`；所有成员可用 `/sug` `/建议`，反馈保存到本地并返回编号。

`/code` `/编程` 默认使用 boost 的独立 pro 工作会话，实际实现与验证后交付代码；主聊天模型不变。`/图片` 生成图片，`/搜图` 搜索现有图片。搜索、处理、分析、总结、翻译和写作命令统一由控制台派发反重力子代理，成果进入持久结果队列，由主代理通过 CLI 批准发送。普通聊天字数限制不截断命令全文与文件；超出文件直发数量会打包 ZIP，保留全部成果。完整语法和配置见 [控制台文档](console_tools/README.md)。

内容工作命令统一携带当前和引用消息的文件、图片等附件，原件保留并复制给工作分支；原生/API 生图均支持传递参考图。主会话通过反重力原生工具白名单关闭终端、编码和任意文件读写，仅能读取控制台列入本轮清单的记忆；实际工作交给独立子代理。聊天常驻规则已精简，保留人设正文并停用桌面编码预设的自动注入。

主代理文字发送使用常驻 `qqbot_cli` 接口，与命令行共用权限、去重和提交事务，省去每次启动 shell/Python 的等待；`reply/commit` 提交后仍可继续安排子代理和其他行动，全部完成后最后调用 `action=finish` 主动结束本轮并发送。`finish` 停止当前主代理生成，保留已提交回复和后台任务，不再靠反复输出“在线待命”结束。升级后重启 QQBot 即可应用，无需修改全局反重力配置。

主代理现可通过控制台 `agents create/send/list/read/close` 申请和反复联系子代理。同一子代理保留身份、模型会话和工作区，按序接收后续消息；不同子代理并行。结果通过内部信箱唤醒主代理，可追问或转交给其他子代理继续处理，无需等待新聊天，也不会自动向群里播报。明确让 bot“自己去玩、去学习”的请求会在回复前提交自主探索任务；空闲时也可自行选择公开内容研究，实际见闻、兴趣和游戏/能力愿望交回主对话。详见[持久子代理与信箱](console_tools/README.md#持久子代理与信箱)。

空闲记忆按连续话题整理，输入保留发言者 ID、昵称、时间和回复关系，同时包含确认发送成功的机器人回复。原始模型请求中的预设、工具协议和内部通知不再当作聊天送去总结；旧日志保留，首次整理会重建旧格式摘要。普通轮次只传当前上下文凭据和新事件，兴趣、愿望与活动反馈只在变化时提供，不再逐轮附送回复模板、空状态或相同的失败详情。

## 🌟 核心特性

- 🚀 **免 API Key 直连**: 通过 Antigravity 本地守护进程与 Language Server 自动中继，调用当前 Google 账号的 Gemini 3.8 / Pro 充足配额。
- 📏 **消息分段与字数约束**: `max_reply_length` 控制单条消息分段，`reply_char_limit` 控制普通聊天整轮字数；按问题需要展开，气泡数量不再固定为三条。命令全文与文件交付不受聊天字数限制。
- 🎭 **纯对话台词 / 动作描写开关**: 提供 `enable_action_descriptions` 开关。关闭时硬性禁止并过滤所有括号动作、神态与旁白描写（如 `（脸红）`、`（耳朵耷拉下来）`），大幅节约 Token 输出；开启时呈现原汁原味的二次元角色扮演。
- 💬 **群聊自主互动 / 插话功能**: 群聊新消息自动进入 AI 判断，无需 @，根据上下文自然接话并承接追问；连续对话不受随机概率或固定冷却截断。可配置空闲主动话题、@ 概率与 `master_id`（主人发言 100% 必定回复特权）。
- 🧠 **群聊专属压缩记忆库**: 基于 JSON 持久化存储每个群的问答历史与群成员画像，支持条目超限自动总结压缩，有效控制上下文长度，并支持 `/name` 绑定群友称呼。
- 🖥️ **现代深色 GUI 控制台**: 基于 pywebview 和 Edge WebView2 构建的图形化控制面板，支持一键启停、实时日志监视、人设工坊、自主插话参数微调与记忆库管理。
- 🎭 **可视化人设预设工坊**: 支持创建、编辑、删除自定义 AI 角色预设（内置雪村ふぶき、傲娇猫娘女仆、系统架构师、温柔学姐、毒舌吐槽姬等），可在 GUI 或 QQ 中随时切换。
- 🤖 **双模支持（官方开放平台 + 本地 QQNT 个人小号）**: 既支持官方 `qq-botpy 1.2+`（需 AppID/Secret），也支持连接本地 QQNT 挂载的个人小号（基于 OneBot v11 / NapCatQQ / LLOneBot 免 AppID 静默运行，0 键鼠占用）。
- 🔍 **双模自检与探针系统**: 启动时自动扫描 Antigravity 进程与连接状态，并执行 AI 探针健康检查。
- 🔄 **本地服务自动重连**: Antigravity 端口失效且明确拒绝连接时，重新发现端口和令牌并重试原请求一次，保留会话 ID；服务故障提示独立处理，不写入对话记忆。
- ♻️ **失效对话自动恢复**：后端确认对话被删除或不存在时，自动创建新对话、重载当前规则和记忆入口，重试当前消息一次并保存新 ID；恢复失败会明确提示。
- 🛡️ **安全政策拦截处理**：识别 Google 敏感词政策提示及结构化安全拦截，立即跳过本轮并释放聊天队列；被直接询问时明确提示，自主插话时静默。受阻消息和图片事实不会自动重放，下一条新消息继续处理；保留原对话和图片存档。
- 💬 **持续主会话**：启动时仅准备本地规则文件，保留会话 ID，不逐群调用模型预热；不同人设分别使用独立主会话与记忆，切回时恢复对应会话。空闲时将新增事件概括到固定记忆文件，新消息取消空闲整理；无新增或同批失败时不重复调用模型。
- 📝 **按需详略与自然分条**：闲聊直接、少套话，解释和步骤按需完整展开；单条分段阈值不限制整轮回答总字数。短句换行可分成多个气泡，长回答保留段落、列表和代码；OneBot 不再只发送前五段。
- 🗨️ **CLI 发送与精确引用**：主代理通过 `message` 发送正文，按需显式指定真实消息 ID 和 @ 对象；默认不引用、不 @，最终文本不会自动发送。群消息仍按固定窗口缓存，标签引用已停用。
- 📨 **回复排队与积压合并**：同一会话默认按顺序回复；积压达到 `bot.backlog_interrupt_messages`（默认 3 条）时，停止当前自然聊天生成及尚未发送的后续气泡，将原轮输入与积压消息按发言人、时间和原始编号一起交给 AI 判断如何回应。已发送、排队投递和回执不确定的内容附给下一轮，避免重复。设为 0 恢复完整回合排队；后台工作、命令与其他会话独立运行。
- 💬 **未完发言缓存**：自然消息发信前，主代理必须合看缓存与当前输入；未说完用 `speech hold` 缓存原话并取消回答，下条消息到来再判断，已说完用 `speech ready` 确认后回复。缓存跨重启保留，按账号、人设、会话版本和发言人隔离；等待期间不定时催问，暂停空闲主动话题。完整接口见[控制台文档](console_tools/README.md#发信前判断与未完发言缓存)。
- 🖼️ **图片与表情包分别理解**：表情包简述情绪、神态和交流含义，普通图片保留可追问细节。分支归档前保存识别事实，再交给主会话；后续追问复用事实与完整结果文件。
- 🙂 **按标签发送表情包**：在控制台导入 PNG/JPEG/GIF/WebP 并填写情绪、动作和语境标签，主 bot 根据群聊选择真实图片发送；保留 GIF 动画，每轮最多一张并遵守群间隔。`[保持安静]` 等独立控制行不会进入 QQ 正文。
- 🎮 **软件自主使用与 galgame 游玩**：主人提供 exe 路径后，独立工作会话截图、输入、滚动、点击；支持浏览器刷视频、看帖子和软件操作，保留专用登录态及观察记录，主聊天继续运行。持续使用需开启控制台调度和单个目标的 autoplay。
- 🛠️ **控制台 CLI 与子代理**：命令统一正则解析后进入控制台，搜索、生图和执行工作使用独立分支。结果排队回到主代理，通过 `deliver` 显式交付全部成果和完成台词。已有文件用 `send` 直接发送；群友上传文件用 `inbox/receive/status` 接收到本地，两者均不调用模型。工具与文档见 [console_tools/README.md](console_tools/README.md)。


视频检查/转码需要 `ffmpeg`、`ffprobe` 位于 PATH，或在 GUI 的“媒体功能与任务”中填写完整路径。现有 `config.yaml` 会自动补齐媒体默认配置；可参考 [配置示例](G:/qqbot/config.yaml.example)，保留自己的凭据与账号设置。

### 步骤 2：配置 `config.yaml`

打开项目根目录下的 [`config.yaml`](file:///g:/qqbot/config.yaml)，填入您的机器人凭证：

```yaml
# QQ 官方开放平台凭据
qq:
  appid: "102xxxxxx"       # 填入您的 BotAppID
  secret: "xxxxxxxxxxxxxx" # 填入您的 AppSecret
  is_sandbox: false        # 开发测试阶段若在沙箱内可设为 true，正式上线设为 false

# Antigravity 本地 Gemini 配额配置
antigravity:
  default_model: "flash"   # 默认模型: flash (Gemini 3.8 Flash), pro (Gemini 3.8 Pro), flash_lite
  timeout_seconds: 0       # 主聊天、任务与识图的 agent 工作均不限时；兼容旧配置
  session_timeout_minutes: 30 # 仅清理辅助临时会话；群聊和私聊主会话保留

# 机器人行为
bot:
  system_prompt: "你是一个由 Google Gemini 驱动的 QQ 智能助手，回答简练、友好、富有条理。"
  max_reply_length: 1200   # QQ 单条消息安全字符上限
  strip_mentions: true     # 自动过滤 @机器人 文本
```

> **注意**：`antigravity` 下的 `ls_address`、`csrf_token`、`language_server_path` 均可**留空**，程序会自动跨进程检测并连接本机正在运行的 Antigravity 实例！

联网查询通过 CLI `search` 交给独立反重力子代理自主检索、浏览和抓取，回答附带实际工具结果中的来源链接，正常终端与脚本工具也可使用。媒体任务默认使用 `media.search_provider: native`：反重力独立完成检索、浏览、抓取和下载，将核对后的成果保存到任务文件夹，结果回到主代理后经 CLI `deliver` 发送这些本地文件。不会先进入 QQBot 的来源页爬取与下载流程，不会使用工作区既有图片替代网络资源；只有取得平台回执后才发送完成台词。

后台任务内置媒体助手（源码：`python -X utf8 media_worker.py`，打包版：`QQBot.exe --home <数据目录> --module media`）。`download --manifest <任务目录内JSON清单> --directory <任务目录>` 根据 `url/path/referer` 逐项流式下载，校验 HTTP、文件签名与完整解码，再原子保存原图；`media_downloads.json` 保存来源、哈希、失败项及恢复进度，重复执行复用通过校验的原文件。`preview --path <原图> --directory <任务目录>` 生成独立、同尺寸的 RGB PNG/JPEG 预览。验图使用预览，交付仍使用原图；灰度、CMYK、WebP 等不再直接进入视觉分支，预览核对记录会绑定原图和预览的哈希。动画预览仅代表首帧，其他帧需按任务要求另行检查。

后台等待会核对原生轨迹中本地日志漏记的终止错误。遇到明确 `INVALID_MEDIA`，工作任务保留原子代理身份、工作目录、原图和已完成成果，保存恢复检查点，隔离出错的原生模型历史后尝试继续一次；原生会话 ID 会更新，旧轨迹保留供诊断。再次失败将回报具体错误，不循环重发。安全拦截、权限拒绝和明确取消不自动重试；主代理收到可修复的子代理错误时通过 `agents send` 向原身份继续处理。

已移除“极速模式 / 思考深度”选择及聊天切换命令：原来的设置只修改提示词，不能控制反重力的推理速度。旧字段迁移只移除设置，保留已有会话 ID 和上下文。公共搜索源仍可在媒体配置中手动选择。

长搜索和资料命令（包括“给我……歌词”）直接进入后台任务队列，使用独立会话执行，群聊继续响应。内容技能的文字结果无论长短都保存为 Markdown 文件发送，聊天只显示简短交付提示。取消任务与查询进度优先进入聊天通道；引用消息会先读取元数据，只有图片识别进入后台队列。官方接口的回复窗口按原消息接收时间计算，窗口结束后通过“任务进度”领取已准备的文件。

QQ 来图默认先尝试窗口截图：普通图片使用已打开且能确认归属的查看器截图，表情包截聊天画面。截图失败后，后台任务使用原消息中的图片来源下载识别。每张图在独立的视觉分支中理解，结果和工具记录保存后归档分支；聊天复用确认的描述，回复由主代理通过 CLI 显式发送；需要引用时指定真实消息 ID。

短时间连续输入仍按缓存设置合并。当前自然聊天生成期间，同一会话积压 3 条原始新消息即触发中断与合并；同一发言人的连续片段即使已预合并，也按原始条数计数。原输入不会丢弃，已发送内容与回执状态交给下一轮参考，AI 自主决定回答哪些问题、如何合并或等待。发送中的单个接口请求会等待回执，尚未发送的后续气泡停止；不中断已提交的后台任务、图片/视频成果交付或管理命令，也不跨账号、人设或会话合并。可在 GUI“设置 → 消息排队”调整阈值；`bot.backlog_interrupt_messages: 0` 关闭。中断后直接处理已积压的整批消息，不再增加一轮缓存等待。

群聊话术表固定在 [`data/slang_glossary.md`](G:/qqbot/data/slang_glossary.md)，可在控制台的 **“运行控制台 & 日志”→“话术表”** 中直接新增、修改、重命名、删除和搜索词条，无需手改 Markdown。编辑表单支持解释、别名、标签和来源，保存时自动更新索引，bot 下一轮聊天即可读取，无需重启。解释留空时，群聊遇到该已确认黑话后会在后台联网补全；已有解释直接用于理解，不重复搜索。

刷新或重新进入话术表页面可读取后台和文件的最新修改；未保存的输入会保留。若同一词条已被后台或其他窗口更新，保存会提示冲突并保留草稿，刷新后再编辑。手改文件仍受支持，须保留 `entries` 和 `index` 区域标记。技能说明见 [`skills/group-slang/SKILL.md`](G:/qqbot/skills/group-slang/SKILL.md)。

### 搜索、生图与命令发送（CLI 2.0）

搜索使用 `search --query`，生成图片使用 `generate-image --prompt`。GUI 媒体页可选择 Gemini 网页端、反重力原生工具或图片 API。当前配置和示例配置使用网页端生图，模型默认 `pro`；当前/引用消息中的原图会直接上传以完成图生图，结果保存后沿用主代理的成果交付流程。`AppConfig()` 的兼容默认仍为 `native`，旧配置可手动切换。

视频生成默认同样使用网页版 Gemini，命令为 `/生成视频 小猫在雪地里向前走`，CLI 为 `generate-video --prompt '小猫在雪地里向前走'`；自然语言要求生成视频时，主代理使用同一入口。附上或引用图片可生成参考图视频，`/图生视频 --model pro 保留人物，让镜头缓慢推进` 可单次选择账号支持的模型。网页版模型和登录态沿用已有 Gemini 网页端设置；GUI 媒体页可单独开关视频生成或切换视频生成方式，配置为 `media.video_generation_enabled`、`media.video_generation_provider`（默认 `gemini_web`）。显式 `--provider native` 使用原生视频生成分支。实际能力和配额由网页版账号决定，未返回真实生成视频时会明确报错；成功后下载并校验成片，保存到任务目录，经主代理批准交付。视频仍在生成时的下载轮询受网页端超时配置限制；下载中断只重试同一成片，不自动重新生成。

网页端需要 Python 3.11+ 和 `requirements.txt` 中的依赖，无需 Gemini API Key。先在常用浏览器登录 [Gemini 网页端](https://gemini.google.com)，再到 GUI“媒体功能与任务 → Gemini 网页端”点“检查登录并读取可用模型”。默认自动识别浏览器最近使用的配置和系统代理；可选择 Chrome、Edge、Brave、Firefox 及具体配置目录。模型支持 `pro`、`flash`、`flash-lite`、`auto` 或账号返回的完整名称，刷新列表会保留已选模型。

可在 GUI 的“Gemini 网页连接”中显式选择“浏览器”连接方式，或设置 `media.gemini_web.transport: browser`。`run_gui.bat` 默认优先启动已安装的编译运行包，使用新源码时可在项目目录的 PowerShell 中运行 `$env:QQBOT_USE_SOURCE = "1"; .\run_gui.bat`。编译运行包需要重新构建后才会包含这项功能。选择自动、Chrome 或 Edge 后点击“打开浏览器登录”，在打开的窗口手动登录 Gemini，关闭该窗口释放专用登录资料目录，再点击“读取账号模型”并保存配置。`media.gemini_web.page_profile_dir` 默认是 `data/gemini_web/page-profile`，相对应用数据目录。原有配置默认使用 `cookie` 连接方式。浏览器页面模式沿用 QQ 的图片、视频、文本、搜索、任务和附件入口，网站及账号提供的控件决定可用功能。普通主聊天仍需要本地 CLI。控制台本身使用 WebView2，Gemini 页面模式使用单独启动的 Chrome 或 Edge 窗口及其专用登录资料，并通过 Playwright 操作网页。网页提供临时对话时会使用该功能，否则可能创建普通对话并保留网页历史。浏览器页面模式支持 `auto`、`flash`、`thinking`、`pro` 模型。

新版 Chrome / Edge 的登录数据可能受加密保护或被浏览器占用。这时点“连接当前浏览器”：在已登录 Gemini 的浏览器配置中，通过 `chrome://extensions`（Edge 为 `edge://extensions`）加载本地 [Gemini 连接扩展](G:/qqbot/browser_extensions/gemini_connector)，再刷新打开的连接页。首次完成后自动同步登录态并读取模型，无需复制 Cookie；QQBot 重启后恢复本机连接，命令行启动也支持接收更新。扩展只同步 Gemini 所需的两项 Cookie，Windows 使用当前用户的系统加密保存，凭据不写入任务、聊天或配置正文。

手动配置仍可用：填写 [Cookie 文件模板](G:/qqbot/gemini_web.cookies.example.json)，或设置 `QQBOT_GEMINI_1PSID` / `QQBOT_GEMINI_1PSIDTS`。优先级为环境变量、手动文件、已连接浏览器、直接读取所选浏览器配置。关闭 `media.gemini_web.auto_browser` 可仅使用手动登录；`auto_proxy` 控制代理环境变量缺失时的系统代理识别。

QQ 示例：附上或引用原图后发送 `/图片 把背景换成樱花，保留人物和构图`；单次选型使用 `/图片 --model pro 把背景换成樱花`。搜索、任务、翻译、写作和附件分析可按需指定，例如 `/搜索 --provider gemini_web --model flash 今日新闻并附来源`、`/处理 --model pro 分析所附文件`。选项放在正文前；省略时这些命令继续沿用原有执行方式。`/model` 仍控制主聊天的反重力模型。网页端生图只接受生成图片，不用搜索图片补充失败结果；网页端生成数量由服务实际返回决定，数量不符时保留文件并报告错误。

登录与模型检查只验证账号连接，图片下载还需要代理能访问 Google 图片服务。下载会逐跳核对 Google 图片服务地址并沿用已配置的代理，兼容本机代理下的 CDN 跳转。遇到临时网络错误时，会使用当前登录态和代理新建连接，重新下载同一张图片一次；此恢复步骤不调用生图。任务失败会区分连接、生成、下载和本地校验等阶段，结果中的 `diagnostic` 仅记录异常类型与网络状态码，不记录 Cookie、请求网址或第三方错误原文。

聊天发送使用 `reply --text` 一次提交；复杂多目标回复用 `message --text` 暂存后 `commit`。回复提交只确认发送批次，同轮仍能继续申请和联系子代理、提交工作或保存个人记录，模型自然完成后封存上下文并发送；不会为提前发出回复而取消原生执行。需要引用或 @ 时显式附加 `--reply-to 真实消息ID`、`--mention 真实成员ID`，用 `messages` 查询可用 ID。默认不引用、不 @，不因新消息或断线恢复而添加引用。旧标签法和最终文本自动发送已停用。

QQ 命令统一进入控制台，由完整匹配的正则语法规范化后分发。后台完成的成果先保存，再排队交给主代理，通过 `deliver --request-id` 交付；主聊天在后台搜索、生图和生成视频期间继续响应。支持 `/search`、`/generate-image`（别名 `/draw`、`/生图`）、`/generate-video`（别名 `/生成视频`、`/文生视频`、`/图生视频`）、`/command`（别名 `/exec`）及 `/help`、`/status`、`/tasks`、`/cancel` 等管理命令。`/video`、`/视频` 用于检索现有视频。完整参数见 [控制台文档](console_tools/README.md)。

### 表情包、软件使用与本地游戏

控制台新增 **“表情包与自主学习”** 页。先填写标签（如“开心,赞同”“疑惑,吐槽”“安慰,摸头”）和适用语境，再导入真实图片；同图再次导入可更新标签。匹配候选由主 bot 结合聊天判断，没合适表情时继续用文字。默认同群间隔 60 秒，排队超过 120 秒的表情不会补发；需同时启用媒体图片发送。

主人可直接在 QQ 发送：

```text
玩一下 "E:\gal2\Template!!\Tenpure.exe"，慢慢阅读剧情，记录你的感受和当前进度。
继续之前那款游戏，读到下一个自然休息点。
看看你之前的游玩和学习记录。
停止游玩。
你去https://www.kungal.com/刷帖子吧
去 https://www.bilibili.com/ 自己看看感兴趣的视频。
用 "C:\Program Files\Google\Chrome\Application\chrome.exe" 打开 https://www.bilibili.com/ ，自己看看感兴趣的视频和游戏帖子。
继续使用之前的浏览器，遇到感兴趣的配乐讨论就记下来。
以后自动继续刷视频，不需要在群里播报进度。

```

主人明确说“你去某网址刷帖/看视频”时，控制台会先提交独立浏览任务，再由主会话简短回应；执行者是 bot，人设不能把要求改成让主人自己浏览。只给网址即可，使用已授权或本机安装的 Chrome/Edge；也可在控制台“默认浏览器”指定路径（`sandbox.browser_executable`，留空自动查找）。聊天中引用的示例和普通网址讨论不会自动启动任务。浏览器缺失、接口关闭或模式不支持时，主会话会收到具体错误。

阅读目的和兴趣由主对话决定。运行中想换题、搜索某作品或追问一段内容时，主对话通过 `sandbox steer` 实时调整原任务，后台停止旧方向并在同一浏览器、账号和模型分支接收新方向；重复使用同一目标的 `use/play/browse` 也会调整现有任务，不再额外排一个争用窗口的任务。主对话会取得带截图依据的页面笔记，可以据此自主选择下一步；新增阅读内容也会安静地送入主对话思考，不自动往群里播报。`direction_revision` 是已提交的方向版本，`applied_revision` 是执行分支已接收的版本，实际读到了什么以页面和笔记为准。

其他软件和游戏的 exe 路径必须来自当前主人的原消息，不能由模型猜测或从页面文本获得授权；继续使用本会话已授权目标。首次使用前在控制台设置主人 QQ 号，刷新 Antigravity 的 MCP 工具并重启 QQBot 载入新代码。MCP 未刷新时可用同一套 CLI 回退，接口和参数见 [控制台工具说明](G:/qqbot/console_tools/README.md)。

控制台 CLI 2.0.0 提供全部公开操作的直接参数：`python G:/qqbot/console_tools/cli.py help sandbox note` 可查询必填项、参数类型、返回字段与完整示例；`context` 返回当前权限、绑定任务及可直接执行的命令，`tasks` 找回自己的任务 ID。笔记可直接用 `sandbox note --text '实际观察' --kind observation --evidence '真实截图ID'`，不再要求构造参数 JSON。多行文本用 `--text-file/--content-file/--task-file`；所有帮助、结果和错误均为 UTF-8 JSON。主对话和执行分支均收到同一公开接口说明，正常操作无需分析源码或数据库。

后台软件和游戏任务默认不限时、不限操作次数，`sandbox.max_actions: 0` 表示不限次数；也可手动设为正数，在达到该上限时保存进度并暂停。阶段性文字（如“正在导航，稍候查看”）只作为检查点保存，控制台会继续同一任务；刷帖子、看视频和自由游玩不会因一轮模型回复或自然休息点自动关闭。主人限定的具体目标确已完成时，工作会话先保存有截图依据的 note，再通过 `sandbox finish` 提交实际结果，验证后才归档完成分支；遇到登录、验证等阻碍使用 `pause`，保留模型会话和记录。运行中工作的工具上下文不会因为经过一天而过期，停止后输入权限随任务撤销。

后台内容拦截会由控制台识别，跳过受阻页面，从站点入口开启干净执行分支；保留同一浏览器、软件窗口、登录态和任务记录，不重放受阻页面、截图或模型历史。连续拦截且没有新阅读进展、或缺少其他入口时暂停。可在“软件使用、游戏游玩与自主学习”中刷新并选中任务，点“跳过当前内容”或“重启执行分支”，也可提供其他入口网址。CLI：`sandbox activities` 查询任务；`sandbox skip --session-id SESSION_ID --url https://example.com/` 跳过到其他入口；`sandbox restart --session-id SESSION_ID` 重建执行分支。均需当前 `--context-file`，用回执里的恢复版本及 `activities.recovery.state=applied` 确认实际恢复，操作不会绕过服务过滤。游戏画面无法自动确定安全的跳过操作时会保留进度暂停。

galgame 默认优先使用 `desktop read`：普通对白由本地 OCR 读取，已加载适配的 Ren'Py 使用当前对白屏幕的文本；每句仍截图、等待文字稳定、单次按键并记录证据，一次最多推进 8 次，再将逐句文本汇总给模型。普通对白不重复上传图片，选项、菜单、明显场景变化、识别不确定、文字不稳定或画面停滞时提前停止并返回真实画面；累计 24 次普通推进也会补充画面。重要对话可单句阅读或主动截图观察表情、演出与 CG。OCR 采用本地启发式识别，特殊布局可调对白区域；无法确认时回到单次看图操作。

在“软件使用、游戏游玩与自主学习”中可开关本地阅读、调整批次大小、对白区域与稳定等待时间，或配置 `sandbox.galgame_reading`。旧配置自动使用默认值；安装更新后的 `requirements.txt` 提供 OCR 所需模型，识别期间无需联网。批次重复调用或中断不会重放按键，主人停止、调整方向和操作次数上限在每次输入前仍会核对。

后台会话保存有真实观察依据的剧情、主观感受或偏好；这些记录不会自动改写人设，也不会变成群友经历。游戏窗口、存档和登录态保留，中断的输入不会在重启后重放。后台工作不向群里自动发送进度、截图或“任务完成”，可询问 bot 或在控制台查看记录。停止会取消排队和运行中的任务，并关闭该目标自主续用；正在投递的单次操作可能完成。

已结束任务的定时自主续用默认关闭；当前运行中的持续任务不依赖这个开关。需要定时再次启动时，先在控制台勾选“开启软件自主使用与续玩调度”，再由主人为已授权目标开启 autoplay；两处都开启才会按间隔继续原来的具体目标。`interval_minutes` 默认 30 分钟是再次调度的间隔，不是任务运行时限。`sandbox.profiles` 为只读资料目录别名；`sandbox.browser_profiles` 为专用浏览器登录目录别名，可在同一页设置。账号与有效登录态由主人提供，不在配置中填写密码。未指定登录目录时为本目标自动创建持久目录；不要使用正在打开的个人浏览器目录。遇到登录、验证码或权限阻碍时保存记录并暂停该目标自主调度，处理后可继续。

Chrome/Edge/Chromium 使用本地页面接口取图、输入中文、滚动、点击和导航；其他 Windows 软件使用客户区截图与窗口消息，兼容性取决于应用。软件会话独立记录真实页面观察（observation）与主观感受，游戏仍单独标注虚构剧情。只看截图不会声称听过音频或看完整段视频。默认浏览和阅读，对外发帖、评论、私信或改账号状态需要主人明确指定。通用软件当前使用 background 模式，QEMU 保留原游戏流程。

默认 `sandbox.mode: background`，游戏在独立 Windows 后台桌面启动，不切换用户桌面或抢占前台。agent 通过控制台 MCP/CLI 执行“客户区截图 → 分析画面 → 窗口按键/带坐标的鼠标消息 → 再截图”循环；不移动系统光标、不使用全局键鼠输入，多个任务按游戏互斥。续玩可以接回该后台桌面已打开的游戏，不接管用户桌面的窗口。

后台操控按窗口结构选择实际内容区，过滤零尺寸辅助窗口、输入法和提示窗口；唯一可信的隐藏或最小化内容窗口会在后台恢复。主窗口被模态对话框禁用时改用该对话框，多个独立内容窗口则返回候选信息。取图会尝试不同的窗口绘制方法并记住成功方法，始终使用客户区坐标。操作后可跟随同一授权目标的新窗口，旧截图不能继续输入，重复调用也不会重放动作。

任务状态区分排队、进程启动和首张有效画面。`sandbox activities` 中的 `launch` 记录启动/附着，`startup` 记录等待次数、耗时和具体错误；只有 `startup.state: ready` 才表示取得画面。启动观察默认等待 60 秒，只重试暂态窗口/取图错误；可在控制台“软件使用、游戏游玩与自主学习”的“启动取图等待”中调整，或配置 `sandbox.startup_timeout_seconds: 60`（1–300）。这只影响启动观察，不限制后续任务时长。`frame_changed`/`window_changed` 描述操作后的像素和窗口变化，实际操作效果仍需核对新截图。

**后台桌面与主机共用文件和权限，不是操作系统隔离沙箱。** 部分游戏引擎不支持后台截图或窗口消息，持续空白或输入无效时停止并记录原因，不回退前台控制。已有 QEMU 环境可显式设置 `sandbox.mode: qemu`；两种模式由控制台“游戏运行方式”选择，保存后重启机器人生效。

## BERT 独立情感工作台

子项目位于 [`emotion_studio`](emotion_studio/README.md)：使用 **pywebview** 制作标注、CUDA 训练和本地分析界面。当前使用独立的 **ACG 专用语料：112,583 句训练、3,855 句银标验证、3,320 句银标测试**，来源为原创轻小说、Galgame 对白及 ACG 游戏评论，不混入通用合成句和公版古典小说；详见 [ACG 语料说明](emotion_studio/data/acg/README.md)。通过三个独立模型投票、助手实际抽样复核、全局去重、整作品/系列及评论作者隔离提高质量，GUI 支持来源图表、标签/复核状态筛选和上下文查看。中文 BERT 使用 LoRA、FP16、序列长度 256、有限权重的温和类别抽样，PyTorch 分配器显存预算 2048MB，并显示实际峰值。训练进程与分析服务完全分离，机器人只调用本机接口。

当前 ACG 验证和测试为自动银标，另有小规模助手盲读参考，均不能视为人工金标；历史启动集和混合版单独归档。显存预算不包含 CUDA 上下文和其他进程占用。数据授权按来源分别记录，公开评论未宣称可再次公开分发。详情、目录结构及独立启动命令见子项目说明。

## 情感接口与旧版分类器

GUI 新增“情感分析与训练”页，包含“模型与分析”“逐句标注”“训练与图表”三个子页。`emotion.provider` 默认 `main`，旧配置继续使用主会话分析。安装更新后的依赖：`python -m pip install -r requirements.txt`。源码更新后，已有 EXE 需重新构建；使用源码可运行 `python gui.py`。

1. **读取已有模型**：在 LM Studio 启动本地服务，填写 `127.0.0.1:1234` 等 `host:port` 地址，点击“读取 LM Studio 模型”，分别选择语言模型和嵌入模型的 key。列表只读取已下载模型；选定模型在首次使用时加载。已有 GGUF 等模型先在 LM Studio 中导入。语言模型使用固定情感标签和结构化输出分析每句话。
2. **逐句标注**：先填写固定标签集（支持自定义，例如 `喜悦, 悲伤`），再粘贴文本“拆句并添加”，逐行选择人工标签。新句子默认“未标注”，不会把模型的猜测自动当作训练答案。支持 CSV、JSONL、JSON 的 `text` / `label` 字段，TXT 导入后需人工标注；可保存、追加及修改标注。
3. **开始训练**：选择“字符特征 + 分类器（CPU）”，可完全离线训练；选择“LM Studio 嵌入 + 分类器”，则通过 SDK 提取句子向量，训练分类头。设置轮次、批大小、学习率、L2、验证比例及随机种子后开始训练。训练前自动保存当前标注文件。
4. **查看真实指标**：模型对每句输出标签概率，以人工标签计算交叉熵并通过 SGD 更新权重。图表逐轮显示训练/验证损失、准确率、宏 F1、混淆矩阵以及各标签精确率、召回率和 F1。相同句子先去重，冲突标签会阻止训练；验证集按标签分层独立留出。划分验证集时，每种已使用标签至少需 2 条不重复样本；验证比例为 0 时不生成验证指标。
5. **保存、回读与继续训练**：按验证损失（无验证集时按训练损失）保存最佳完整轮次的 `.npz` 分类器，内含权重、标签顺序、特征信息和训练历史。点击“读取分类器”恢复分析和图表；“载入模型训练设置”恢复标签、特征并启用继续训练。继续训练沿用当前权重，新的轮次从 1 开始记录。停止任务时保留已完成轮次的最佳模型；首轮尚未完成时不覆盖已有模型。指标可导出 JSON。
6. **用于机器人**：选择“LM Studio 语言模型”或“本地训练分类器”，保存配置并重启机器人，`/emotion` 即通过同一隔离证据和发送回执流程返回逐句分类。大段材料会读取完整证据文件；模型失败会记录错误，不会自动改用主会话。图片沿用已有视觉识别，再对已确认的描述文字分类。

LM Studio 的 Python SDK 名为 `lmstudio`，通常写作 `import lmstudio as lms`。它提供推理与嵌入，**不提供大模型权重训练 API**。本功能训练的是可保存、回读的 softmax 情感分类器，嵌入模型保持冻结；`.npz` 分类器由 QQBot 读取，不能作为 GGUF 导入 LM Studio。使用嵌入特征的分类器在分析时也需要相同的嵌入模型和本地服务。语言模型不返回可校准的类别概率，GUI 对其概率栏显示 `—`；分类器显示实际 softmax 概率。

标注文件示例（JSONL，每行一句一个固定标签）：

```jsonl
{"text":"今天收到礼物，很开心。","label":"喜悦"}
{"text":"终于完成任务，真高兴！","label":"喜悦"}
{"text":"想到这件事就很难过。","label":"悲伤"}
{"text":"离别让我有点伤心。","label":"悲伤"}
```

本地接口可独立调用：

```python
from config import EmotionConfig
from emotion_training import read_dataset, train_classifier
from emotion_models import analyze_sentences

cfg = EmotionConfig(provider="local_classifier", labels=["喜悦", "悲伤"])
rows = read_dataset(cfg.dataset_path, cfg.labels)
result = train_classifier(cfg, rows, on_progress=lambda event: print(event))
predictions = analyze_sentences(cfg, ["今天真开心！"])
print(predictions[0].as_dict())
```

配置字段见 `config.yaml.example` 的 `emotion` 段。训练及 GUI 回归可运行 `python -m pytest test_emotion_local.py test_emotion_command.py test_gui_modernization.py -q`，测试在隔离副本中执行，不连接运行中的 QQ 或 LM Studio。

## 🧩 架构原理解析

```
+------------------+         +------------------+         +----------------------------+
|  QQ 用户 / QQ 群  | <=====> |  qq-botpy 网关   | <=====> |   GeminiQQBot (bot_client) |
+------------------+ (WebSocket)+----------------+         +--------------+-------------+
                                                                          |
                                                                          v
+-------------------------------+         +-------------------------------+
| Google Gemini 3.8 账号配额     | <=====> | AntigravityClient             |
| (本地 Language Server 直连中继)|         | (antigravity_client.py)       |
+-------------------------------+         +-------------------------------+
```

1. 用户在 QQ 客户端发送消息，腾讯网关通过 WebSocket 将事件推送至 [`GeminiQQBot`](file:///g:/qqbot/bot_client.py)。
2. [`GeminiQQBot`](file:///g:/qqbot/bot_client.py) 解析指令并提取文本，路由给 [`AntigravityClient`](file:///g:/qqbot/antigravity_client.py)。
3. [`AntigravityClient`](file:///g:/qqbot/antigravity_client.py) 自动通过本机的 Language Server 与 AgentAPI 创建/追加会话，使用当前 IDE 登录的 Google 账号配额完成 Gemini 推理。
4. 模型生成的回答由 [`AntigravityClient`](file:///g:/qqbot/antigravity_client.py) 捕获后，经长文本智能段落切分，由腾讯官方 API 发送回 QQ 聊天窗口。

## 图片、视频和文件

在 OneBot 群聊中先 **@机器人**，私聊可直接发送。主人账号也可直接发起群媒体任务。普通自主插话继续走文字聊天。输入 `/media` 可查看帮助。

| 可以这样说 | 实际行为 |
| --- | --- |
| 搜三张橘猫图片发我 | 检索并校验后发送图片，附来源；失败候选会尝试同页后续结果，不足时说明实际数量 |
| 找一张9:16星空手机壁纸 | 检查图片真实尺寸和比例；没有匹配结果时说明原因 |
| 发个生气猫猫表情包 | 先在已登记资料库按文件名匹配，再查公共图片源；建议素材命名为“生气猫.png”等 |
| 引用图片：把这张图作为文件发我 | 发送当前可获取的图片附件；支持群聊、私聊和机器人刚发出的图片，不保证 QQ 原消息提供的是未压缩原图 |
| 搜几个一分钟以内的猫咪视频 | 搜索来源页并提取视频源；未提取到文件时保留原页面候选 |
| 把第二个视频发过来 | 从本人最近候选中选取，尝试抓取、下载并验证/转码；仍无法获取时返回原页面与原因 |
| 下载并发送这个网页里的图片 https://example.com/gallery | 抓取用户提供的公网来源页，解析资源并下载；也支持媒体直链 |
| 搜 Python 官方教程 PDF 发我 | 从实际官方文档下载页定位 PDF 包并提取教程，明确文件版本；最新版没有 PDF 时查 3.13、3.12 官方页 |
| 把上一条回答整理成 txt 发我 | 生成完整 UTF-8 附件，支持普通回答和最近搜索列表 |
| 把这些数据整理成 CSV 文件：姓名,分数… | 使用冒号后的数据生成 CSV；也可导出最近回答中的逗号数据或 Markdown 表格 |
| 查群文件里的活动通知，发最新那份 | OneBot 本群文件查询，按可验证的上传时间选择；最多扫描根目录和 10 个一级文件夹 |
| 把资料库里的安装说明发我 | 单个匹配直接发送，多个匹配列候选；“最新”按本地文件修改时间选择 |
| 发第二个 / 第二张换一张 / 下一页 | 选择本人结果或换一批，默认结果保留 15 分钟；不会使用另一名群友的搜索结果 |
| 任务进度 / 取消刚才的下载 | 查询/领取已准备资源或停止在途任务；不会自动撤回已提交的消息 |

精确指令：`/image 关键词`、`/video 关键词`、`/file 关键词`、`/library 关键词`、`/groupfile 关键词`、`/pick 2 [结果ID]`、`/next`、`/task [任务ID]`、`/cancel [任务ID]`。公共来源候选每页最多 5 个，反重力任务没有这项限制。成果按账号、会话和发起者隔离。引用图片查询在 OneBot 中支持缓存及同会话 `get_msg`，官方通道使用近期消息缓存。

| 通道 | 图片 / 短视频 | 通用文件 |
| --- | --- | --- |
| 同机 OneBot / NapCat | 已校验本地文件的 `image` / `video` 消息段 | `upload_group_file` / `upload_private_file` |
| 跨设备 NapCat | 分块上传、校验 SHA-256，取得远端路径后发送 | 同一上传流程；网关需支持 `upload_file_stream`，可用 `napcat_stream_enabled` 关闭 |
| 官方 QQ 群 / C2C | 先上传取得 `file_info`，再发送富媒体；本地生成/转码资源需要 HTTPS 发布接口 | 默认返回真实来源链接；生成文件无链接时需要发布接口。仅确认应用支持后开启 `official_file_enabled` |

官方回复预算按群聊 5 分钟、C2C 60 分钟、每条入站消息最多 5 次管理，说明文字与媒体共用序号。例如三张图会使用 3 条媒体及说明文字的回复额度。超过窗口/次数时资源留在 `ready`，用户再次发送“任务进度”使用新窗口领取。接口超时或断线后的未确认发送保留 `unknown`，请核对聊天记录，查询状态不会自动重发。

图片首期支持 PNG/JPG/GIF/WebP/BMP，视频支持 ffprobe 能验证的 MP4/WebM/Ogg/MOV 等容器，并按需转为 H.264/AAC MP4；官方通道优先 PNG/JPG 和 MP4。普通附件支持 PDF、ZIP、DOCX/XLSX/PPTX、UTF-8 TXT/CSV/MD/JSON/LOG；图片/视频也可明确要求“作为文件”发送。音频附件与语音编码暂未接入。

可选公共下载器默认限额为图片 10 MB、视频 50 MB、文件 1024 MB、视频 120 秒、同时处理 2 项；这些公共下载设置不限制反重力工作；交付统一跳过超过 1 GB（1024³ 字节）的单文件。临时任务独立并发，不设对话数量上限。文件交付数量不限，超过 20 个本地文件自动打包 ZIP，较大时分成多个独立 ZIP；接近 1 GB 且 ZIP 头会导致超限的单文件保留原文件发送。缓存按通道/账号分目录，默认 TTL 24 小时、容量目标 2 GB；新任务启动时回收非活动缓存，在途文件会暂时占用额外空间。不要把配置、会话或记忆目录登记成资料库。GUI 的“媒体功能与任务”提供开关、限额、来源配置、ffmpeg 状态、缓存统计、任务日志与发送结果预览，配置保存后重启机器人生效。

默认 `search_provider: native` 将发图技能、图片/视频/资料搜索以及链接下载直接交给反重力。agent 自主决定检索词、访问网页、浏览器操作、脚本抓取、下载与重试，不设固定网页数、操作次数或下载总时限。成果保存在 `media.cache_dir/<账号命名空间>/tasks/<任务目录>/`，交付清单为 `delivery.json`。QQBot 只登记并发送任务目录内的本地成果，不再次下载、转码或缩放，也不强加分辨率、方向和大小条件。图片先在本轮真实打开，并记录主体、身份与类型核对；可复用任务的看图证据，不必逐张另开视觉会话。来源不要求出现在初始搜索白名单；文件存在、归属和实际平台回执仍会校验。可手动选择 `auto`（Bing + Wikimedia）、`wikimedia` 或自定义接口使用公共下载器。

OneBot 的命令进入持久化后台任务记录并独立并发执行，普通群聊使用各自的有序聊天队列和会话。耗时任务不会阻塞后来的图片和表情包识别；控制台在收到图片时即显示识别状态，完成后更新原条目。`run_task` 可完成较复杂的检索、网页操作、资料整理和文件制作，检查成果后交付。主聊天与后台 agent 工作均使用 `timeout=0`，旧版 `antigravity.timeout_seconds` 不会终止任务；`media.task_timeout_seconds` 只管理公共下载器。平台发送与上传仍按实际传输结果记录状态。群消息默认使用 `bot.chat_buffer_seconds: 5` 的固定缓存窗口，可在配置页“群消息固定缓存窗口”调整到 0–300 秒。窗口结束后统一读取群成员的新消息并回复；回复期间收到的消息进入下一批，回复完成后重新计满一个窗口。普通文字和图片资料共用该批次；明确控制命令仍可即时处理。固定窗口不因新发言持续延长，也不再让下一批发言取消已开始的一批回复。`0` 兼容旧的 `chat_settle_seconds` / `chat_max_wait_seconds` 合并方式。每条消息都保留真实消息 ID 和发送者 ID；主代理通过 CLI `messages` 查询，再用 `message --reply-to ID` 或 `--mention 成员ID` 显式指定，默认不引用、不 @。不同发言人的身份与主人权限保持独立，引用消息不授予原作者的权限。

`bot.max_reply_length` 只控制单条消息的分段阈值，例如配置为 100 时，完整回答仍可超过 100 字并多条发送。确认、测试和接梗直接回应，详细问题按需展开；普通聊天的独立短句换行可形成多个气泡，详细说明的自然段不再被合并为最多三组。超过阈值优先在换行或句末拆分，URL 保持完整。OneBot 保留全部发送段落，离线时也逐段缓存；官方通道按剩余被动回复额度合并相邻段落，仍受平台实际长度与窗口限制。新规则会在现有对话下一次接收消息时更新，无需清空聊天记忆或重新核验人设。

搜索、下载等明确任务从规划阶段进入工作队列，包括 CG 检索。实际执行使用每个任务独立的反重力会话，不继承聊天会话的人设、短回复规则或默认等待时间；命令的 AgentAPI 请求同样不限时。群聊中的 `web_search` 与资源下载共用完整任务流程，保留原始要求，自主决定检索范围、工具、脚本、下载和实际查看方式。

每个任务拥有持久工作目录，可以保存网页、脚本、中间结果、下载和解压文件，没有 bot 施加的目录容量或下载大小配额。反重力可把交付 JSON 写入 `agent_result.json`，最终回复无需重复整份清单。未形成有效交付或成果校验未通过时，bot 会保留已有文件并在同一任务会话继续执行，没有固定重试次数；只有完成、明确失败、取消或反复返回完全相同的停滞状态才结束。原始响应与工具记录保存在工作目录，未完成任务不会触发会话删除。

任务子会话通过 `agent_result.json` 提交完成请求，控制台校验后保存 `delivery.json` 和完整结果文件，再把结果排队回原主会话。主代理通过 CLI `deliver` 批准全部已验证成果并指定完成台词；已有文件可通过 CLI `send` 直接批准。文件逐项取得平台回执后才发送完成台词，最终文本不会触发发送。任务交付使用独立后台流程，新聊天及图片分析不会截断上传。OneBot 消息确认默认等待 30 秒，RPC 额外保留 5 秒；`sendMsg` 回调超时记为 `unknown`，保留记录且不自动重发。

文字回复写入 `data/runtime.sqlite3` 后发送；断线期间保留待发送内容，重连后依序发送。媒体文件准备好后等待连接；已准备结果可以通过“任务进度”领取。没有收到发送回执的操作标记为“状态未知”，不会自动重发，也不会误报任务完成。进程重启时未完成工作标记为“已中断”，可查询并重新提交。QQ 官方通道仍受平台回复窗口和次数限制，剩余文件或完成通知会等待同会话新消息续发，已发送文件不重复。

`bot.qq_window_capture: true` 先由 QQBot 使用 Win32/UIAutomation 本地算法核对 QQ 账号、聊天与原消息，再把截图保存为文件；agent 不参与窗口定位、截图或控制台操作。表情包截取对应消息区域，普通图片仅在已打开且能确认归属的查看器中截图。程序不操作键鼠或切换聊天；窗口最小化、无法唯一定位或校验失败时，进入第二阶段：使用原消息的 `file` 标识调用 `get_image`，必要时从同会话 `get_msg` 刷新真实来源，验证并下载/复制到图片缓存。不会构造缺失链接或搜索磁盘原图。定向来图和引用识图都进入后台队列，普通群聊继续运行；未涉及机器人的图片只记上下文。截图或原图文件准备好后，独立视觉分支只接收真实绝对路径，实际查看文件、保存识别归档后清理分支，回复由主代理通过 CLI 显式发送；需要引用时指定真实消息 ID。主对话只使用确认的画面描述，不接收截图操作指令。

群记忆以文件方式接入：启动时不预加载全部群的历史正文。普通对话只给 agent 当前群的绝对文件路径和精简索引，新会话直接读取当前记忆 JSON（含总结、人物和永久预设），历史归档按需读取；同一会话复用已读结果，明确要求刷新或出现新归档时再读取。QQBot 不再把记忆正文和人物总结拼入每轮聊天提示，`/memory` 仍可显式查看记忆。

群记忆默认每 30 分钟及停止时归档。程序把每个账号和人设的完整消息、模型生成的总结保存在 `data/memories/profiles/<身份哈希>/packages/group_<群号>/<运行开始时间_运行ID>/`；同一次运行复用同一归档包，固定最新摘要为该人设目录下的 `group_<群号>.summary.json`。索引保留为原有 JSON 格式。写入并回读校验后清理已完成的临时检索和视觉分支，普通群聊及私聊会话 ID 保留，重启后继续原对话。空闲、普通请求超时、临时服务错误、停机取消都不清空主会话；切换人设选择独立主会话，切回恢复该人设自己的会话；明确清空、切换模型、主人权限等其他配置变更或后端确认原会话不存在时才重建。归档期间新收到的消息留到下一批，失败保留原文和检查点。控制台停止、重启、关闭窗口会等待记忆保存完成。

模型日志中的 `API error (attempt N)` 若为 503 服务繁忙或网络暂态错误，会保留当前回复轮次，等待后端在同一次请求中重试；后续消息继续排队，不重复提交原输入。通过只读状态确认后端已停止且日志完整后，仍无结果才报告服务故障并释放队列；状态查询暂时失败不会清空会话。下一轮会收到已核验的失败原因，不能把服务繁忙推测为新消息触发超时取消。

记忆整理由宿主程序负责写文件，每批先保存输入和运行状态，再调用模型；读取完整日志中的第一份有效回复后立即停止该次后台生成。已完成批次直接复用，失败、超时或中断的同一批资料不在定时器、启动或退出时自动重试；内部接口 `summarize_and_save_session(..., retry=True)`、`summarize_activity(..., retry=True)` 可显式重试，`force=True` 只跳过数量和时间阈值。每批默认限时 120 秒，后续新资料继续增量整理。普通对话只收到摘要文件引用，按需通过 CLI 分页读取。

群归档、主会话空闲整理和各个经历目标分别复用固定的整理会话，保留原有账号、群和人设隔离；周期归档不再删除整理会话后重新创建。空闲超时、进程重启和取消整理都保留 ID，创建后在发送首条消息前立即保存映射，避免发送失败遗留无主会话。旧版本排队中的整理会话删除任务会撤销，本地归档保留。整理只使用本次输入的 `previous` 和 `records`，完整规则在新会话或规则变更时发送；禁用工具、子代理及全局预设继承。此机制防止后续反复创建，不根据标题批量删除已经遗留的历史会话。

固定存储位置：

- 群聊：`data/memories/profiles/<身份哈希>/group_<群号>.summary.json`；完整运行消息和批次检查点保存在同目录的 `runs/`。
- 主会话事件：`data/main_chat/<会话哈希>/memory.json`；原文为 `events.jsonl`，输入和进度分别为 `memory-input.json`、`memory-progress.json`，批次检查点为 `memory-work.json`。摘要复用独立整理会话，保留主会话 ID。
- 网页浏览、软件使用和游戏体验：`data/sandbox/memories/<目标ID>.json`；待整理资料和批次检查点分别为同名 `.sources.json`、`.work.json`。完成部分及时落盘，原始观察保留在 `data/sandbox/sandbox.sqlite3`，仅已成功概括的记录推进游标。

独立任务核对通过、成果文件和交付清单保存后，即登记后台临时会话的自动删除，无需等待主代理审核或 QQ 发送完成；结果仍由原控制台队列交给主代理发送。删除前保留可用的完整会话日志，失败自动重试，重启会从已保存的成功任务恢复清理；正在执行、失败待续和暂停的分支保留。启动自检探针在成功、失败或取消后也会自动归档删除，旧探针及切换账号前未删除成功的探针继续重试。

删除对话的后端错误可能使用 `conversation`、`cascade` 或 `trajectory` 命名，发送阶段和等待阶段均会识别，CLI 成功退出但 JSON 内含错误也会处理。等待日志连续 5 秒没有进展时，使用只读原生轨迹查询检查运行状态及漏记的终止错误，查询不可用时再用 `get-conversation-metadata` 确认存在性；后续检查至少间隔 15 秒，查询不调用模型，不在启动或每条消息前预检。普通对话只有确认不存在才重建，同一轮最多一次；查询超时、临时断线或慢日志会保留原对话。后台任务的 `INVALID_MEDIA` 使用上述专门恢复流程。有效的模型空回复仍表示主动沉默；服务错误不会被当成沉默吞掉。

旧版已经删除的主会话若保留了 `conversations/<会话ID>.jsonl.gz` 和删除归档凭据，程序会校验群号、会话 ID 与选中的归档文件，流式恢复完整对话到本群归档包，再作为 `archive_messages` 文件索引供 agent 按需查阅；不会把已删除的旧 ID 重新绑定为活跃会话。

识图分支把完整画面描述、不确定项、原消息 ID 和视觉证据写入 `data/image_context.sqlite3` 及 `data/image_facts/`。下一轮普通群聊自动收到待交接的识图事实；相关追问或引用可直接检索这些结果，不依赖临时分支仍然在线，也无需重复识图。结果按账号、通道和群/私聊隔离，重启后仍能使用；长结果提供完整 JSON 文件路径按需读取。

自主参聊开启后，群聊新消息自动进入 AI 判断，无需先 @。模型根据上下文决定是否开口，并自然承接正在进行的交流、追问、短句和接梗；本轮不回复不会影响下一条消息。旧配置中的 `reply_probability` 和 `cooldown_seconds` 已停用，仅保留读取兼容性，不再限制发言；关闭“群聊自主参聊”可停止普通未 @ 消息的自主回复。

“有见闻或愿望时主动聊天”单独开启，默认每 10 分钟给一次开口机会，仅对本次运行收到过消息的群生效。可以分享真实见闻、延续讨论，或提出想玩的游戏和想要的能力；没有值得说的内容就安静，不强制问候、找话题或提问。“永不休眠”决定是否持续尝试；关闭后可设置空闲休眠时间。新消息会取消尚未发出的旧话题，官方通道还需要有效回复窗口。

“空闲时独立思考与浏览”与主动聊天分开控制。设置 `bot.self_activity_enabled: true`（同时开启 `autonomous_enabled`）后，主代理在已交流过的会话中，每隔 `self_activity_interval_minutes` 分钟的空闲时间获得一次独处机会，默认 20 分钟。它可延续自己的兴趣、记下感受或愿望，也可以休息；独处思考不会发送 QQ 消息，新消息优先打断思考。同一会话连续三次选择 `wait` 后停止空闲自由活动提醒，第三次也不会再自动补派探索任务；暂停状态随会话保存，重启仍有效，收到新聊天消息后重新计数。正常完成一次自由活动会清零连续等待次数，普通聊天、阅读反馈和其他内部事件的 `wait` 不累计。关闭开关会取消尚未完成的独立思考和自主阅读。

独处时可自行选择公开网址，通过现有后台浏览器实际阅读。自主阅读使用独立身份和专用浏览器目录，不借用主人的登录目录，也不自动开启游戏或安装软件；观察和感受使用原有笔记机制保存，完成后的见闻仍能回到主会话。一次具体兴趣得到满足后结束，不无限刷新。登录或能力不足时暂停，主代理可以保存愿望，之后在合适的聊天时机向主人提出。

兴趣、简短感受与愿望保存于控制台数据库的 `companion_life` 表，按账号与角色会话隔离，重启后保留。相同愿望去重，并区分待提出、已提过、已实现和被拒绝；标记状态不会自动授予权限。人设预设只保留身份、性格与关系，常驻规则负责交流和工具协议，不再每十轮重复表演人设或重发完整技能清单。

自定义 `search_api_url` 收到 GET 参数 `q`、`kind`、`limit=5`、`offset`，可从 `QQBOT_MEDIA_SEARCH_KEY` 环境变量读取 Bearer token。返回示例：

```json
{
  "results": [{
    "title": "猫咪短视频",
    "url": "https://media.example.org/cat.mp4",
    "source_url": "https://example.org/watch/cat",
    "duration": 25,
    "width": 1280,
    "height": 720,
    "author": "作者",
    "license": "许可标记"
  }]
}
```

接口不得要求机器人读取任意本地路径。程序忽略返回的 `local_path`、任意 RPC 元数据等字段，并重新验证下载内容。只返回视频网页时可将 `url` 留空，保留 `source_url`。

可选的 `publish_upload_url` 是用户已有的 HTTPS 存储服务：接收文件原始字节的 POST，读取 `Content-Type`、`X-Asset-ID`，可从 `QQBOT_MEDIA_PUBLISH_TOKEN` 读取 Bearer token，返回 `{"url":"https://..."}`。服务应仅发布该请求文件并管理地址有效期，保证腾讯可访问。项目不会自动启动公开文件服务器，也不会映射整个工作区。

## 通讯录、成长预设与主动结束

bot 可通过控制台 `contacts list/show/upsert/delete/history` 持久记录真实账号、称呼、历史昵称、绰号、说话方式及习惯；同名异人不合并，删除不被旧归档复活。`/name`、`/nickname` 与通讯录同步。账号、人设、群聊及私聊资料隔离，启动后恢复相关人物，完整信息按需查询。

主代理可根据自身群聊行为、主人要求和真实阅读反思，通过 `preset show/update/history/reset` 修订可回退的个人成长层，下一轮增量生效，保留基础身份和会话。每次群记忆或空闲记忆归档后会持久安排一次主代理整理机会，进入同一回复队列；退出或失败后继续。详见[通讯录与预设 CLI](console_tools/README.md#通讯录与个人成长预设)。

通常先 `reply` 或 `commit` 提交正文，再完成通讯录、预设和其他 CLI 操作，最后由 bot 执行独立 `finish` 后停止。自然最终文字不会直接结束或发送；原会话会提示完成剩余操作。`wait`/`speech hold` 仍用于明确选择等待。
